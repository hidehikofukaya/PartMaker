# 分岐ファミリ（実車026）設計 — 2026-09-05

## 0. 工学的な本質

ユーザー指定（2026-09-05）:

> 3つ以上の面を締結したいという目的に対して、その面同士をつなぐ面を作って繋ぎ、
> それを一枚のメタルシートから製造可能になっているか、という工学的課題

つまりこの族が学習させたいのは「**締結したい面が3つ以上あるとき、それらを1枚の板で
どう繋ぐか**」であって、単なる形状の多様性ではない。したがって設計の中心は
**一枚板から作れるための条件**（§4）に置く。

## 1. なぜ既存の族では作れないのか

生成器は「1つの断面を、共通の折り軸 w のまわりで掃引する」構造しか作れない。
パネルは必ず**一列の鎖**になる。実車026は鎖ではなく**分岐**している。

軸の取り方に依らない判定（同程度の大きさのパネルが3枚以上つながるか。フランジは
細い付属物なので数えない）:

| 部品 | 最大接続数 | 判定 |
|---|---|---|
| 007 | 1 | 鎖 |
| 011 | 2 | 鎖（次数4のハブはフランジ由来の誤検出だった） |
| 014 | 3 | 分岐だが分岐元が面積11mm²の極小スライバ＝実質は鎖 |
| **026** | **3** | 面14(971mm²) → 面1(1453) / 面18(1652) / 面10(348) |
| 1285-7 | 1 | 鎖 |

> 先に「026ははぐれ軸1本の惜しい候補」と報告したのは誤りだった。あの判定は
> 折り軸 w の選び方に依存して不安定で、w を変えるとはぐれ軸0本にも4本にもなる。

## 3. 構築 — ハブ＋腕

新しい掃引エンジンは要らない。**ハブを平面1枚として作り、各腕をその根本エッジを
軸に回転掃引する**。腕ごとに軸が違ってよいのは、軸が「その腕の根本エッジ」だから。

```
ハブ多角形（平面、凸）
  └ 各辺 e_i について
       e_i を軸に R_i で φ_i 折る        → 曲げ面（円筒、軸 = e_i）
       接線方向へ L_i まっすぐ            → 腕パネル
       腕の先に締結点（必要平面つき）
```

共有エッジは構築上まったく同じものになるので縫合できる。

### 技術的な未知は解消済み

`tools/probe_branch_hub.py`（ハブ＝凸四角形、3辺に腕、折れ角25〜110°、R5〜20、
腕長20〜60mm）で **20/20 = 100%** が縫合でき、既存の全ゲート（ゲートA・外形ループ
1本・二面角・ゴミエッジ）を通った。

## 4. 一枚板から作れるための条件

| # | 条件 | 扱い |
|---|---|---|
| (a) | **展開可能** — 全ての面が平面か円筒で、円筒の軸が隣接平面の交線に平行 | 構築上保証（平面＋回転掃引しか作らない） |
| (b) | **展開図が自己交差しない** | **凸ハブなら構築上保証**。凸多角形の内角は180°未満なので、隣り合う辺の外向き法線は互いに離れる方向を向き、腕の展開矩形は共有頂点で接するだけで重ならない |
| (c) | **ハブ頂点の逃がし（bend relief）** | **要実装**。隣り合う2辺に腕が付くと共有頂点の材料が両方の曲げ帯に属する。実物では必ずノッチを入れる |
| (d) | **腕どうしが3Dで干渉しない** | **要実装**。展開図が重ならなくても折った後にぶつかりうる。既存 `check_shape` は縫合済みシェルの妥当性しか見ないので面の貫通を拾えない |
| (e) | **締結面が確保される** | 既存の必要平面ルールを踏襲（腕の先に `min_bearing_radius_mm` の平地） |

(b) を凸ハブで構築上保証するのは、このプロジェクト共通の
「実行可能な上限を計算してからその中でサンプリングする」方針と同じ。
凹ハブを許すなら (b) は実測ゲートに格上げが要る。

## 7. 判断と実装（2026-09-05）

| # | 論点 | 決定 |
|---|---|---|
| ① | 腕と締結点 | 腕3〜4本、各腕の先に1〜2点、ハブに0〜1点、締結点に応じた余肉カット |
| ② | 2段目の分岐 | 1段のみ |
| ③ | 腕の中の曲げ | 根本1曲げのみ。折れ角は腕ごとに独立で 25〜110° |
| ④ | ハブのコーナー | 各角に1つ、**頂点中心の円弧**でくぼませる（両端の接線が腕の側端エッジに一致） |
| ⑤ | 腕先の余肉 | 矩形を保ち、先端の隅だけ最小R |
| ⑥ | ガセット | **無効**（下記） |

### 7.1 ハブのコーナー — 2回の作り直し

1. 「凸の面取り＋腕ごとの半円ノッチ2つ」→ 多すぎる。角ごとに1つに。
2. 「曲げ線に接する円弧」→ 腕の側端エッジと90°で折れる。**ハブ頂点そのものを中心とする
   半径Rの円弧**なら両端の接線が曲げ線に直交し、腕の側端エッジと滑らかに繋がる。

### 7.2 ガセット — 検討したが無効にした

実車026の実態: 面6は平行な2本の曲げ（軸どうし1.2°）に挟まれた**帯**で、角は11枚の
自由曲面パッチ（484mm² = 3.6%）で**絞って**埋めている。展開可能ではない。

一枚板（平面＋円筒）で角を閉じる方法を3つ検討した:

| 方法 | 結果 |
|---|---|
| 両側を曲げで留める | 角に「ハブ・腕・ガセット」3枚が集まり扇形角の和 90+90+ハブ角 < 360 → **展開不能** |
| 逃がしを残して帯を渡す | 角に窓が開き境界ループ2本 |
| 片腕から折ったタブをもう片腕に重ねる | 展開可能・境界ループ1本で成立（40/40）。**しかし目視では角に穴が残って見える** |

ユーザー裁定: 穴が残るならガセットは無し。`BRANCH_GUSSET_PROB = 0.0`。機構
（`_gusset_faces`、`check_shape(expected_loops=)`）は残してあり、埋め方が決まれば戻せる。

途中で潰した不具合: タブの曲げ始点が腕の壁より 0.18mm 内側にあり縫えなかった
（角の位置と弦の向きの1回更新で打ち切っていた → 不動点反復で自己整合）。
