# 多様性拡張の計画(2026-09-04)

対象: OCCT バックエンド(`occt_build.py`)の上で、部品族の多様性を広げる
発端: ユーザー「基準面曲げが2回強制なのを1回や無しにも対応したい。締結点同士が近い場合は
ビードやフランジが立てにくいのでリブ(曲げの内角方向にひし形状のくぼみ)を設けたい」

**この文書は決定ではなく、判断材料です。**数字はすべて 2026-09-04 に実測したもの。

---

## 0. 30秒サマリ

* **今日の部品は「2曲げ」がほぼ100%**(300部品中3枚パネル 97〜100%)。1曲げは 0.5%、0曲げは 0件。
  1曲げの構成コードは既にあるが、**「2曲げが無駄なときだけの救済」として封印されている**
  (`SINGLE_FOLD_MIN_EXCESS_RAD = 30度`)。封印を解くと **点対の約36%** で1曲げが成立する。
* **締結点が近い部品は今のサンプラーが引いていない**(断面距離 120〜220mm 固定)。
  40〜80mm 帯では2曲げの成立率が 35%。座面半径を絞ると **66%** まで上がる。
* **補強が付かない部品が既に多い。** 現行の 120〜220mm 帯ですら **34%** はビードもフランジも
  載らない。60〜100mm 帯では **72〜84%**、40〜80mm 帯では **86%** が無補強になる。
* **リブは、その穴をほぼ完全に埋める。**曲げ部にリブを置く余地は全帯で **99.4〜100%** ある
  (前後の直線区間 中央値 26〜35mm、凹側半径の余裕も全件クリア)。
* リブは ML 側の要求 §4.1 優先度3「複数特徴 … **折りをまたぐリブ**」そのもので、
  同時に「`run_out` が全部品 1.00 固定で検証不能」という指摘も解消する(OCCT 版のランアウトは可変)。

## 1. 実測: 今の多様性はどこで止まっているか

### 1.1 締結点間距離(断面距離)を振ったときの成立率

座面半径 12.5〜25mm(現行)、各帯 300〜400 試行。

| 断面距離 | 2曲げ計画 | ビードの余地 | フランジ可(最大折れ≤20度) | **無補強** |
|---|---|---|---|---|
| 40–80mm | 35.0% | **0.0%** | 13.3% | **86.7%** |
| 60–100mm | 70.7% | 3.8% | 13.2% | **83.5%** |
| 80–120mm | 94.0% | 14.2% | 15.6% | **71.6%** |
| **120–220mm(現行)** | 94.0% | 56.0% | 19.5% | **33.7%** |

* ビードは「2×座面半径 + ランアウト + 本体」を中心線上に要求するので、短い部品には**原理的に載らない**。
* フランジは最大折れ角 ≤20度 が条件なので、距離に関係なく 13〜20% で頭打ち。
* **現行帯ですら 1/3 が無補強**。ここが一番大きな空白。

### 1.2 40–80mm で落ちる理由

| 棄却 | 40–80mm | 80–120mm | 120–220mm |
|---|---|---|---|
| `free_fold_seed` が解けない | **63.0%** | 5.8% | 0.2% |
| 傾き上限超過 | 0.8% | 3.2% | 4.8% |
| 通過 | 33.8% | 91.0% | 95.0% |

`free_fold_seed` は中間折れ目の位置を `座面半径 + 接線長 + slack` で置く。座面半径が 12.5〜25mm、
接線長が 10〜20mm なので、**両端の予算だけで 45〜90mm** を食う。40〜80mm の分離距離では
2つの折れ目を置く余地が物理的に無い。

**座面半径を 12.5〜15mm に絞ると 35.0% → 65.7% に上がる。**
(直径25mm 最小則は破っていない — 12.5mm は下限そのもの。上限側の引き方を距離に合わせるだけ。)

### 1.3 曲げ数を設計変数にしたときの到達範囲

`SINGLE_FOLD_MIN_EXCESS_RAD` のゲートを外して、点対ごとに 1曲げ構成が成立するかを測った。

| 断面距離 | 2曲げ | **1曲げ** | 1曲げのみ成立 | 0曲げ可(自然発生) | 1曲げの折れ角 中央値 |
|---|---|---|---|---|---|
| 40–80mm | 35.8% | 18.0% | 2.8% | 2.5% | 95.4度 |
| 80–120mm | 92.5% | 32.5% | 0.0% | 1.0% | 97.4度 |
| 120–160mm | 97.2% | 37.2% | 0.0% | 0.2% | 81.9度 |
| 160–220mm | 99.0% | 36.2% | 0.0% | 0.5% | 63.1度 |

**正直な読み方**:

* 1曲げは **点対の約36%** で成立する。今それが 0.5% しか出ていないのは封印のせい。
  **新しい族としての価値は十分**(L字ブラケットは実車の定番形状)。
* ただし **1曲げは短距離帯の救済にはならない**(40–80mm で18%、「1曲げのみ成立」は2.8%)。
  短距離の壁は曲げ数ではなく**座面予算**。§1.2 の対処が本筋。
* 0曲げ(平板)は自然発生が 0.2〜2.5% しかない。**専用の点対サンプラーが要る**
  (法線が平行 かつ 2点が同一平面上)。

### 1.4 リブを置く余地

曲げの前後の直線区間に 3mm ずつのランアウトが取れ、かつ凹側半径 R−深さ が 5mm 以上残るか。

| 断面距離 | 曲げ隣接の直線区間 中央値 | 両側ランアウト可 | 凹側半径OK | **リブの余地** |
|---|---|---|---|---|
| 40–80mm | 26.2mm | 99.4% | 100% | **99.4%** |
| 80–120mm | 29.9mm | 100% | 100% | **100%** |
| 120–220mm | 35.2mm | 100% | 100% | **100%** |

**リブは全帯でほぼ確実に載る。**ビードが 0% の短距離帯でも 99.4%。

## 2. 提案A: 曲げ数を設計変数にする(0 / 1 / 2)

### 現状

`plan_general_two_point` は
1. `single_fold_layout` を試す → **「2曲げが30度以上無駄に曲げているとき」だけ**採用
2. それ以外は `free_fold_seed` + `solve_free_fold` の3パネル固定

### 変更

曲げ数を**先に分布から引く**(ML側の哲学「本数を先に決めない = 個数は分布からサンプルし、
実際の値を報告する」に沿って、狙いが外れたら実際の本数を記録する)。

| 曲げ数 | 構成 | 実装 |
|---|---|---|
| 2 | 現行の自由折れ目チェーン | 変更なし |
| 1 | `single_fold_layout`(既存・検証済み) | **ゲート `SINGLE_FOLD_MIN_EXCESS_RAD` を狙い依存にする**だけ |
| 0 | 平板(1パネル) | 点対サンプラー(平行法線+同一平面)+ プランナに1パネル分岐 + `_build_path` の w 決定を `frames[0].v` にフォールバック |

`occt_build` 側は 1曲げは**既に動く**(素の2パネル部品が3面で出ている)。0曲げは
`_build_path` が折れ目軸を `axes[0]` から取るので、そこだけ手当てが要る。

### コスト/リスク

小。`classify.py` の既存関数をそのまま使う。0曲げの点対サンプラーが新規(〜40行)。
リスクは「0曲げ部品は形状としてほぼ自明」で学習価値が薄いこと — **配分は少なめを推奨**。

## 3. 提案B: 締結点間距離を広げる(120–220 → 60–220mm)

### 変更

1. `SECTION_DISTANCE_RANGE_MM` を広げる。
2. **座面半径を距離に連動させる**: 短い部品では 12.5mm 側に寄せる
   (実測: 40–80mm 帯で 35.0% → 65.7%)。直径25mm 最小則は維持。
3. 帯ごとにクォータを持つ(現状のクラス偏り 73倍を放置しないため。
   `generate_general_batch(class_quota=...)` の仕組みをそのまま距離帯にも使う)。

### 効くこと

* 実車の締結間隔分布に寄せられる(引継ぎ書 §4.4「実車 joints.json 923件から分布を取る」)。
* 短距離帯は**リブ専用の部品族**になる(ビード0%、フランジ13%、リブ99%)。

### リスク

短距離帯は歩留まりが落ちる(66%)。ただし棄却は OCCT に触る前の純Python判定で、
成功部品あたり 0.11秒 なので**実質無料**。

## 4. 提案C: リブ(新しい補強プリミティブ)

### 4.1 何を作るか

**曲げをまたぐ、凹側(内角側)へ押し込んだ局所的なくぼみ。**中心線に沿って走り、
曲げ線の位置で最も広く/深く、前後の直線区間でランアウトして平地に戻る。
平面視のフットプリントは**六角形(先を落としたひし形)**。

```
     平面視                        側面視(曲げを伸ばした図)
  ┌──────────────┐
  │      ╱‾‾‾‾╲       │        ────╲______╱────   ← 凹側へ深さ d
  │    ╱  リブ  ╲     │             ↑曲げ線
  │  ╱__________╲   │
  └──────────────┘
   ランアウト  本体  ランアウト
```

### 4.2 なぜ今の構築原理にそのまま乗るか

`occt_build` は「1本の断面を中心線に沿って掃引する」構造で、**断面は s(経路長)の関数として
差し替えられる**。ビードは既に「平地 → ランアウト → ビード断面 → ランアウト → 平地」を
やっている。リブはその区間を**曲げの周辺に移すだけ**:

| | ビード | リブ |
|---|---|---|
| 区間 | 2×座面半径 から反対端まで(長い) | 曲げの前後だけ(短い) |
| 断面 | 9要素(平地/足R/壁/稜線R/頂部/…) | 同じ9要素(寸法が小さい) |
| 立ち上げ向き | 曲げ上の半径が大きくなる側を自動選択 | **凹側に固定**(ユーザー指定の「内角方向」) |
| 曲げ上の面 | 円錐/トーラス/円筒 | 同じ |
| 幅のテーパ | 無し(帯) | **有り**(ランアウトで幅も絞る → 六角形) |

幅のテーパは、ランアウトの「平地側の断面」のブレークポイントを**内側へ寄せる**だけで出る
(`brepfill.Face` は要素ペアを直線織りするので、y座標を寄せれば台形になる)。
新しい面種は出ない。

### 4.3 設計変数(案)

| 変数 | 案 | 根拠 |
|---|---|---|
| 深さ | 2〜6mm | 曲げR(10〜22.5mm)の凹側で R−d ≥ 5mm を満たす |
| 頂部幅 | 6〜20mm | 半幅(12.5〜25mm)から足R後退量+余白を引いた残り |
| 壁角度 | 45〜70度 | ビードと同じ(プレス成形の常識値) |
| 稜線R | 中立面R最小(5mm)以上 | 全半径の絶対条件 |
| 本体長 | 曲げ弧長 + 前後 3〜10mm | 曲げをまたぐことが目的 |
| ランアウト長 | 深さの2倍(空き次第で短縮、下限3mm) | ビードと同じ規則 |
| フットプリント先端 | **真の菱形(1点に収束)** | ユーザー決定(§9)。`ThruSections.AddVertex` で作り、退化の安定性を実測で確認する |

### 4.4 派生して手に入るもの

* **2曲げ部品には曲げが2つ = リブ2本**が置ける → ML 側 §4.1 優先度3「ビード2本」相当の
  **複数特徴部品**が無料で出る。
* **リブ + フランジ**、**リブ + ビード**の同居も、区間が重ならなければそのまま成立する。
* 「ビード/フランジ/リブの区別が連続体になる」ことを ML 側は既に観測しており
  (主成分2つで98%)、その実証材料になる。

### 4.5 代替案(採らない理由つき)

| 案 | 内容 | 判断 |
|---|---|---|
| R1 六角テーパ(**推奨**) | 上記 | 解析面のみ。ランアウトのみ直線織り面 |
| R2 平行帯(テーパなし) | 幅一定でランアウトは深さだけ | 実装は最小だが「ひし形」にならない |
| R3 真の菱形(先端が点) | ランアウトの端を1点に潰す | 退化ロフト。OCCT で不安定。**非推奨** |
| R4 曲げ線に平行な横リブ | 曲げをまたがない | 曲げの剛性に効かないので設計として誤り |

## 9. 決定事項(2026-09-04、ユーザー判断)

| # | 決定 | 備考 |
|---|---|---|
| 1 | **リブは真の菱形(先端が点)** | 六角テーパ案は不採用。先端は `ThruSections` の `AddVertex` で1点に収束させる。退化ロフトになるので、`BRepCheck_Analyzer` と幾何合格判定で必ず検証し、不安定なら報告する |
| 2 | **締結点間距離は60mmまで下げる。その代わり短距離帯は締結点の位置関係を拘束する** | ①面のねじれを許容しない(横ズレ dw = 0) ②曲げ0〜1回 ③曲げ角は鋭角にならない |
| 3 | **曲げ数の配分は 2曲げ60 / 1曲げ35 / 0曲げ5** | 狙いが外れたら実際の本数を記録する |
| 4 | **1部品の補強は1つまで**(複数特徴は不採用) | リブ2本・リブ+フランジは作らない |

### 9.1 決定2の解釈(実装時の定義)

* 「面のねじれを許容しない」= 締結点2を **w(共通折れ目方向)に直交する平面内**に置く
  (`dw = 0`)。結果としてパネルのシアーが消え、折れ目軸は厳密に w に一致する。
* 「曲げ角は鋭角にならない」= **外向きの折れ角 ≤ 90度**(パネル同士のなす内角 ≥ 90度)。
  部品が自分の上に折り返さない、の意。
* **適用範囲**: 締結点間距離 < 120mm を「短距離レジーム」とし、この拘束を課す。
  120mm 以上は現行どおり(2曲げ可・横ズレ可)。

### 9.2 決定2にともなう構築方法の変更(重要)

短距離帯を「点対を引いてから解く」方式で作ると、拘束下の成立率は **23〜33%** にしかならない
(実測、60–80mm で23%)。原因は、折れ目の交線が締結点の後方に来る配置を引いてしまうこと。

そこで **1曲げ族と0曲げ族は逆向きに作る**: 先に形状パラメータ
`(d1, d2, 折れ角, 曲げR, 座面半径, 半幅)` を引き、そこから締結点2を導出する
(feasible-by-construction。この方針はプロジェクトで一貫している)。

実測(2000試行):

* 構築成功率 **65.9%**(落ちるのは `R > 0.9×半幅` の事前棄却で、Rを半幅の後に引けば解消する)
* **往復誤差 2.13e-14** — 導出した締結点から `single_fold_layout` を呼ぶと、設計した
  `d1 / d2 / 折れ角` が厳密に復元される。既存の `plan_general_two_point` →
  `occt_build` の経路をそのまま通せる
* 距離分布は `d1 / d2` の slack レンジで自由に制御できる(上記試行では中央値77mm)

2曲げ族は現行どおり「点対 → `free_fold_seed` → `solve_free_fold`」を使う。

### 9.3 決定4にともなう簡略化

補強は1部品1つなので、`occt_build` の断面差し替えは「s の区間が1つだけ」で済む。
`_sweep_with_bead` を `_sweep_with_feature(regions)` に一般化する必要はあるが、
`regions` の長さは常に1でよい(将来の複数特徴に備えて形だけ開けておく)。

## 11. 修正(2026-09-04、ユーザー指摘3点+確認1点)

### 指摘1: 大きめの部品なのに特徴が無いものがある

**原因**: バッチ実行スクリプトの既定 `reinforcement_probability = 0.9`。補強の解決自体は
失敗していなかった(**1491件中0件**が「どの補強も付かない」)。無補強が20.7%まで増えたのは、
補強を狙わない試行はビルドが一発で通るぶん出力に多く残るため。

**修正**: 既定を **1.0** に。補強が付かないのは `resolve_reinforcement` が None を返す場合
(=締結点が近すぎて何も載らない)だけになった。再生成した300部品は **無補強 0件**。

### 指摘2: ビードの終端が三角にすぼんでいる

**確認の結果、ビードは健全でした。**指摘の部品 `0008` は `bead=None / flange=None / rib=有`
で、**リブのみ**の部品です。三角にすぼんで見えていたのは旧リブの先端で、ビードのランアウトは
従来どおり幅一定(平面視で終端が四角)のままです。指摘3の修正で解消します。

### 指摘3: リブの形が違う(八面体の半分が内角側へ出っ張るイメージ)

**原因**: 旧リブは「曲げ弧 + 前後の body_margin(3〜10mm)」を full section の平坦な稜にし、
その外側にノーズを付けていた。ノーズ長も深さ基準(2.5×深さ)だったため、**細長い稜線**になり、
菱形に見えなかった。

**修正**:
* full section は **曲げ弧そのものだけ**(`body_margin` を廃止)。前後は即ノーズで点へすぼまる。
* ノーズ長を**幅**基準に変更(`nose_ratio` = 0.8〜1.6 × フットプリント半幅)。
  縦横がほぼ等しい菱形になる。
* 結果、平面視は菱形、立体では稜が曲げ線上に来て内角側へ出っ張る形になる。

**なぜ「曲げ弧だけを稜」にするのか(構築上の要請でもある)**: 曲げ弧の上は回転掃引で厳密な
円錐/トーラスになる。もし断面を s に沿って連続的に縮めると曲げの上も直線織り面になり、
**部品の側端が円弧ではなく弦の折れ線**になってしまう。曲げ弧=稜/直線区間=テーパ とすれば、
菱形の見た目と側端の厳密さが両立する。

### 確認: 1部品1特徴

**満たしています。**`occt02` の300部品を検査して複数特徴は **0件**、再生成した `occt03` でも0件。

## 12. リブの再定義(2026-09-04、ユーザーの指示訂正)

### 生成条件

**「ある程度の折れ角の曲げがある」かつ「締結点が近すぎてビードが置けない」ときだけ。**
満たさなければリブは作らない(以前は「フランジ対象外の45%」で振り分けていた)。

* 折れ角の下限 = **45度**(ユーザー決定)
* 「ビードが置けない」は**構造的に**判定する — `general_geometry.bead_room_mm()` が
  「2×座面半径 ×2 + ランアウト ×2 + 本体5mm」を中心線長から引いて負なら不可。
  ビード寸法のサンプリング運では決めない。

### 形状: 正四面体の半分

四面体 V1-V2-A-B を内角に押し付けた形。V1V2 は曲げ線上、A はパネル1、B はパネル2。
面 V1V2A / V1V2B はパネルに乗っているので、**中立面に現れるのは V1AB と V2AB の2面**。
稜 **A-B は曲げ線に直交** する — ここが以前との決定的な違いで、稜が曲げ線と平行だと
曲げの開きに対して効かない。

### 工程(他の特徴と違う)

基準面を**シャープな折れ**のまま作ってリブを置き、そのあと**リブ幅の外側だけ**を
フィレットする。リブ部品の曲げRは**中立面R最小 5mm に固定**(ユーザー決定)。

構築は断面掃引ではできない(パネルの境界が曲げ線のところで V 字になり幅方向に一定で
ないため)。リブ部品だけ面を明示的に張る経路にした:

```
|y| >= c+t      通常の円筒フィレット(MakeRevol、厳密)
|y| in [c, c+t] 円弧から鋭角へ落ちる遷移(頂点Vへのロフト)
|y| <  c        フィレットせず、リブの三角形 V1AB / V2AB
パネル          平面多角形1枚(境界にV字を織り込む)
```

### 踏んだ不具合

1. **接線長の出どころ**: `plan.fold_tangents` は法線どうしの角度から出ており、
   ここで使う「wまわりの符号付き角」と0.2度ほどずれる。R=5mmで94度回すと
   **0.8mmの食い違い**になり遷移ロフトが接続しない。自前の折れ角から計算し直した。
2. **パネルの原点**: 自由折れ目チェーンでは `origin` が折れ目そのものだが、
   **単曲げでは `origin` が締結点にあり折れ目は `near_run_mm`**。取り違えて
   パネルが巨大なスリバーになっていた。

### ビード判定の副次的な修正

「ビードの余地はあるのに不成立」が1500件中210件あり、無補強が14.5%まで増えていた。
原因はCATIA時代の `check_bead_feasible`(全パネルに平坦なビード区間を要求 —
probe-and-select 構築のための条件)。断面掃引には不要なので、OCCTが実際に使う条件だけを見る
`check_bead_feasible_occt` に差し替えた(無補強 14.5% → 3.4%)。
`emit_feature_truth` の `plan_bead_on_surface` 依存も外した。

### `occt04/chunk_01`(300部品)

```
invalid 0 / 最悪プリミティブずれ 0.000000mm / ゴミエッジ 0 / 複数特徴 0
ビード249(距離 中央151mm) / フランジ27(181mm) / リブ6(89mm) / 無補強18(108mm)
```

## 13. リブの稜線フィレット(2026-09-04)

### 最初の結論は誤りだった

「OCCTのシェルフィレットはこの形状に使えない」と報告したが、**診断を読んでいなかった**。
`StripeStatus` を見ると **2 = WalkingFailure**(輪郭に沿った進行の破綻)で、
半径にも曲面種類にも依らなかった。そこで最小構成で切り分けた:

**平板2枚が90度で交わるコーナーに同じ四面体リブを置くと、頂点が尖ったままでも
R5 / R3 / R2 すべて成功する。**

つまり四面体そのものは問題なく、原因は**周囲のトポロジー**だった。

### 真因

フィレットの遷移ロフト(円弧 → 頂点)が作る**退化頂点が、リブの角 V1/V2 と同一点**に
あった。リブの底辺 V1A / V1B がその退化頂点で終わるので、walking がそこで破綻する。

### 修正

リブのフットプリントより **2.5mm 外側までシャープな折れを残す**(`RIB_SHARP_MARGIN_MM`)。
これで退化頂点はリブの角から離れ、V1/V2 は「パネル1・パネル2・リブ三角形」が集まる
普通の頂点になる。プローブで **全辺R5 が 8/8** に。

### 併せて必要になったガード

フィレットが通っても、**頂点ブレンドの境界が解析曲線にならない**ことがある
(実測で最大 **0.797mm** ずれ、300部品中24件がゲートA違反)。さらに通っても
無効なシェルになるものが5件あった。構築側に2つ足した:

* `MAX_PRIMITIVE_DEVIATION_MM = 0.25` — 1本の直線/円弧から外れたら部品ごと棄却
* `BRepCheck_Analyzer` が無効なら棄却

リブの歩留まりは 1/23 になるが、棄却は安いので全体で 0.6秒/部品。

## 14. 形状の崩壊: 原因と検知(2026-09-04、ユーザー指摘)

### 見つかった崩壊

`occt07/chunk_01/SYN_general_two_point_0048` が崩壊。従来のQA(`BRepCheck` 有効・
プリミティブ適合・ゴミエッジ)は**全部通っていた**。違いは**自由エッジ60本**
(健全なビード部品は16本)。段階を追うと**縫合の時点で88本**開いていた。

### 原因

ビードの開始位置を「端パネル固定」から「逃げが取れる直線区間を探索」に変えた際
(§13の前段)、**ビードが曲げより後ろから始まるケース**が生まれた。ところが
`_sweep_with_bead` は曲げ区間を**無条件でビード断面**で掃引していたため、前後の
平地断面と噛み合わず、全ての区間境界で縫合が失敗していた。

修正: 曲げの中点がビード区間 [s1, s2] の内側かどうかで断面を選ぶ。ランアウトは必ず
直線区間の中にあるので、曲げは区間の内か外のどちらかに完全に入る。
0048 の自由エッジは 60 → 16 になった。

### 検知の仕組み(2つ)

**(1) 外形は閉じた1本のループでなければならない** — `boundary_loop_count()`

穴を開けない方針なので、開いたシェル1枚の板金部品の外形は必ず1本の閉ループになる。
面がばらけると面ごとに開いた辺が残り、ループ数が跳ね上がる。自由エッジを頂点で
つないでループ数を数えるだけなので安い。**これが最も確実な崩壊の兆候。**

実測(occt07 の300部品を後から走査):

| 外形ループ数 | 部品数 |
|---|---|
| 1(健全) | 273 |
| 3 | 11 |
| 5 | 16 |

**27件の崩壊を検出**した。従来のQAでは1件も引っかからなかったもの。

**(2) 隣接面の折れ角が異常でないこと** — `worst_dihedral_deg()`

ユーザー提案の「勾配が異常な形状は怪しい」の実装。中立面は自分の上に折り返らないので、
隣接2面の法線が180度に近く開いていれば掃引の破綻(ねじれ・面の裏返り)を意味する。
実測の健全値:

| 族 | 中央 | 最大 |
|---|---|---|
| ビード | 27度 | 70度 |
| リブ | 47度 | 85度 |
| フランジ | 2度 | 5度 |
| 素 | 0度 | 0度 |

上限は **150度** に置いた(健全の最大85度に対して十分な余裕がある)。
今回の崩壊は「面は正しいが繋がっていない」型なので(1)でしか捕まらないが、
ねじれ型の崩壊は(2)が捕まえる。両方とも構築側で検査して、外れたら部品ごと棄却する。

### 併せて厳しくしたもの

* プリミティブ適合の判定を12点サンプル → 24点(粗いと0.84mmのずれを見逃した)
* リブを数mm大きく(`MIN_RIB_HALF_WIDTH_MM` 7→10、`MIN_RIB_LEG_MM` 9→12)し、
  シャープ帯を 2.5→4.0mm に。小さいリブはフィレットの条件が悪く、失敗するか
  OCCTが長時間止まる(222試行中111がフィレット失敗、バッチが停止した)。
  これで リブの歩留まりは 4.5% → 6.9%、平均試行 23回 → 15回。

メモリ上のシェルで判定していたが、**STEPの往復で曲線が再近似される**ことが分かった
(実測: メモリ上0.25mm以内だったフィレット稜線が、読み戻すと **0.839mm** ずれていた)。
下流が読むのはファイルなので、書き出してから読み戻して検査し、落ちたらファイルごと
削除して引き直すようにした。

## 15. ビードを当初の要綱に戻す(2026-09-04、ユーザー指摘)

### 何が壊れていたか

* ビードが基準面の折れ目をまたがない(片方のパネルだけに載る)
* 締結点付近で走り終いの壁がほぼ垂直になる

### 当初の要綱(roadmap Step 3、2026-08-21)

> 両端のパネルで、締結点からの距離が `2*min_bearing_radius_mm` 未満の区間は
> ビードを平地に戻す「端の逃げ」を追加した

つまり **ビードは両端の座面を避けつつ全長を貫通する**のが前提。折れ目の位置は
`座面半径 + フィレット接線長 + slack` で決まり、**ビードが成立するまで slack を
選び直す**(`resolve_bead_slacks`)ことでエラーを最小化していた。

### 私が壊した経緯

§14の前段で「大きいのに特徴がない」を直したとき、ビードの開始位置を
**「逃げが取れる直線区間の探索」**に変えた。置き場所を動かして解決したので、
折れ目をまたがないビードが生まれ、逃げも空き次第で3mmまで縮んだ。
**解決すべきは置き場所ではなく折れ目の位置**だった。

### 修正

1. `bead_placement` を両端固定に戻す(開始 = `2×座面半径`、終了 = 全長 − 同)。
   ランアウトが端パネルの平坦区間に収まらなければ、その配置は不成立。
2. ランアウト長は **深さの2倍で固定**(最低8mm)。空きに合わせて縮めない。
3. `families.bead_part` が **slack を16回まで引き直して**ビードが通る折れ目位置を探す。

実測: ビード族 60/60 が全ての折れ目をまたぐ。300部品バッチでも **150/150**。
ランアウト長/深さ の比は最小 2.00。

### 併せて直したもの

* **リブのフィレットが発散してバッチが停止**していた。原因はリブ三角形 V1-A-B の
  **内接円半径がフィレット半径より小さい**こと(c=10・脚12・折れ角90度で内接円4.6mm
  < R5)。3辺のフィレットが重なるため OCCT が収束しない。
  `triangle_inradius_mm() >= 1.3 × R5` を成立条件に追加し、寸法は大きい側から引く。
* 空のSTEPが返るケースをValueErrorにしてバッチが落ちないようにした。
* **締結点が面の上にあること**を検査に追加(実測: リブ部品1件で締結点が
  **23.9mm** 面から外れていた。部品が自分の座面に届かない型の崩壊)。

## 17. 本番生成とリブの作り直し(2026-09-04)

### リブが落ちる理由(250試行の層別)

| 段 | 件数 | 割合 |
|---|---|---|
| **ゲートA(プリミティブずれ)** | 199 | **79.6%** |
| フィレット失敗 | 15 | 6.0% |
| 無効シェル | 10 | 4.0% |
| ゴミエッジ | 10 | 4.0% |
| 成功 | 6 | 2.4% |

**フィレットの失敗より、フィレットが「通ったあと」のずれが支配的**だった。
成功は折れ角60度未満の帯にしか出ない(60度未満9.4% / 60度以上0%)。

ずれの実値を測ると **中央値 0.625mm / p90 0.999 / 最大 1.095mm**。
正しい許容(0.25×板厚 = 0.25〜0.625mm)を使っても **33件中2件しか通らない**。
`ChFi3d_Rational` などの曲面種類を変えても改善しない。
**頂点ブレンドの境界は原理的に解析曲線にならない**ので、この経路では50%に届かない。

### 作り直し: 丸みを演算ではなく構築で作る

曲げ線に直交する各断面で、シャープな角を**両パネルに接する円弧**に置き換え、
半径を中央で大きく、リブの端で基準面の曲げRに落とす:

    rho(y) = R_bend + (rho_max - R_bend) * (1 - |y|/c)

* 接線長 T(y) = rho(y)·tan(φ/2) が y に線形 → **フットプリントは菱形**
* パネルとの境目は**接線連続**(角が立たない)、稜線も円弧なので丸い
* |y|=c で基準面の曲げRに一致 → **フィレットと連続**、遷移帯も退化頂点も要らない
* エッジは全て直線か円弧、面はランアウトと同種の直線織り面
