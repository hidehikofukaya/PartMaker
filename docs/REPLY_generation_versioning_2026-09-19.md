## 1. 世代の明示(依頼 8 ①)

### 1.1 入れたもの

| 場所 | キー | 意味 |
|---|---|---|
| `<chunk>/manifest.json` | `generation` | 族ごとの連番。**同じチャンク名に作り直した回数**(並存するチャンクは族の中の通し番号) |
| | `generated_at` | 部品を作り終えた時刻(UTC、ISO 8601) |
| | `git_commit` | 生成に使ったコミット(未コミットの変更があれば `+dirty`)。後から刻印したものは `null` |
| | `supersedes` | この チャンクが置き換える旧チャンク(例 `["occt22/chunk_01"]`)。無ければ `[]` |
| | `generation_backfilled` | 後から刻印したチャンクだけ `true` |
| `<chunk>/params/<id>.json` | `generation` | `{"n", "generated_at", ...}`。manifest と同じ値 |
| `<chunk>/variants/manifest.json` | `base_generation`, `base_generated_at` | 変種を作った相手の部品の世代 |
| `<chunk>/variants/params/*.json` | `generation` | 元の部品の世代 + `variant_emitted_at`(変種を作った時刻) |

**照合のしかた**: 部品の params と変種の params の `generation.generated_at` が一致していれば同じ世代です。
一致しなければ組にしないでください。

### 1.2 今後の運用(こちらで仕組みとして強制した)

- **再生成は新しいチャンク名で出す**。`run_occt_batch.py` は既存のチャンクへの上書きを拒否するようにした
  (例: occt22 を作り直すなら `occt22/chunk_02`、manifest の `supersedes: ["occt22/chunk_01"]`)。
  旧チャンクは消さずに残すので、取り込み済みのデータが突然変わることは無くなる。
- 変種を足すときは、変種 manifest の `base_generated_at` が元の部品の manifest と違えば `emit_variants.py` が止まる。
- `tools/check_generation_consistency.py` で「変種の締結点 = 元の部品の締結点」「変種の STEP が元の部品より新しい」
  「params の刻印 = manifest」を全チャンク照合できる。**2026-09-19 時点で全 14 チャンク・変種 50,027 本、問題 0**。

## 4. `structure` の全族展開と座面比(依頼 8 ④、撤回返答 §2 の契約)

### 4.1 `structure`

`batch_generate.structure_of` で計算(occt21/22/23 の生成時と同じ関数)。全族共通キー
`family, joints, hub_gon, walls, sewn, relief, flanges, deep, arms, tabs, beads, rib, notches, folds, panels`
(occt22 は `group` も)。その族に無い因子は 0。変種の params にも入れた(構造変種は元の部品と値が違う)。

### 4.2 座面比 `structure.seat_ratio_min`(元の部品のみ)

| キー | 内容 |
|---|---|
| `seat_ratio_min` | min_k( 締結点 k から**部品の全エッジ**までの 3 次元最短距離 / 締結点 k の必要座面半径 )。全エッジ = 外形 + 折り線 + ビードの足 + フィレットの接線。**09-09 以降の生成ゲートと同じ定義** |
| `seat_ratio_outline_min` | 同じく外形(自由エッジ)だけで測った値。09-09 より前のゲートの定義 |
| `bearing_radii` | 締結点ごとの必要座面半径(mm) |
| `bearing_radii_source` | 半径の出どころ。`spec.min_bearing_radius_mm`(部品で 1 つ)/ `spec.box.point_radii` など(点ごとに記録)/ occt30/chunk_01 だけ復元値(下記) |

そちらの「その締結点の面の辺だけ」より**厳しい**定義です(隣の面の辺も 3 次元で近ければ拾う)。これで 1 以上なら円盤の定義でも 1 以上です。

| occt12, 13, 15, 16 | 1.000 | 1.000 | 0 |
| occt17 | 1.394 | 1.001 | 0 |
| occt18 | 1.044 | 1.000 | 0 |
| occt19 | 1.030 | 1.000 | 0 |
| occt20 | 1.000 | 0.921 | **1**(`SYN_general_two_point_0067`、不足 0.8mm) |
| occt21 | 1.197 | 0.966 | 0 |
| occt22 | 1.137 | 0.988 | 0 |

## 5. occt18 の別シード再生成(依頼 8 ⑤)

### 5.1 何を引き直したか

**締結点と spec(板厚・座面半径・腕の向き・タブ)は固定**し、分岐族の生成器が乱数で決めているものだけを全部同時に引き直した:

| 項目 | 範囲 |
|---|---|
| 腕の長さ(タブ以外の全腕) | U(30, 70)mm。ただし締結点を載せるのに要る長さ以上 |
| ハブの隅 R | U(6, 12)mm |

(knob の変種は 1 つずつ動かすが、こちらは全部を同時に動かす。)

### 5.2 出力

- 対象: occt18 は `_val_ids.json` に無いので、他族のホールドアウトと同じ 20 部品おき 30 部品(`SYN_general_two_point_0001, 0021, …, 0581`)。
- 既存の変種の契約にそのまま載せた: `knob = "reseed"`、`value = "s1".."s5"`
  - `variants/<id>__reseed=s<k>_mid.stp`、`variants/params/<id>__reseed=s<k>.json`、`variants/features/...`
  - `variants/manifest.json` の `changed` に元の値と新しい値、`seed_salt` に乱数の種
- 150 本すべて成功(失敗 0)。締結点が元の部品と一致することを照合済み。occt18 の変種は 3,800 → 3,950。

### 5.3 こちらで測った散らばり(参考)

`tools/measure_variant_spread.py --knob reseed occt18`。外形を 3mm 間隔でサンプル、元の部品と各シードの外形の距離を**両方向**、
u = 締結点の最近傍間隔の平均(**そちらの u とは定義が違う**、撤回返答 §3 参照)。

| 最近傍の締結点まで | 別シード 150 本 中央 / p90 | knob 変種(40 対)中央 / p90 |
|---|---|---|
| 0〜0.5u | 0.030 / 0.111 | 0.013 / 0.078 |
| 0.5〜1.0u | 0.039 / 0.168 | 0.021 / 0.147 |
| 1.0〜1.5u | 0.045 / 0.363 | 0.016 / 0.222 |
| 1.5〜2.0u | 0.047 / 0.428 | 0.000 / 0.176 |

読み: 別シードは knob 変種より**中央値で 2〜3 倍**散り、締結点から離れるほど p90 が大きくなる(0.11u → 0.43u)。
「締結点から遠い部分は入力で決まらない」ことの教師側の証拠です。モデルの誤差との比較はそちらの u で測り直してください。

## 6. 変種を幾何の距離で分ける(撤回返答 §2 の要望、未着手)

`arm_len=d0` のように寸法 knob でも構造が変わる例があるのは同意です。ただ 5 万本の両方向距離はこちらの計算機で数時間かかるので、
先に決めたいことがあります:

1. 距離の定義: 上の §5.3 と同じ「外形の両方向ハウスドルフ / u」でよいか
2. 閾値: 別シードの p90(≈ 0.1〜0.4u)を「同じ設計の中の揺れ」の上限とみなす、でよいか

決まれば `variants/manifest.json` の各エントリに `outline_distance_u` を足します(名前ではなく数値で渡すので、閾値はそちらで選べる)。
