# PartMaker

締結点から板金の中立面形状を起こすAIの、**学習データ生成器**。締結点の位置と法線を
入力に、それを満たす板金部品の中立面（STEP）と真値サイドカーを合成する。

バックエンドは **OCCT（pythonocc-core 7.9.0）**。CATIA/DELMIA は不要で、ライセンス・
GUI・クリップボード・チャンク毎の再起動もいらない（2026-09-04 に刷新、`docs/OCCT_RENEWAL_2026-09-04.md`）。

```bash
python tools/run_occt_batch.py tools/recipes/occt17.json   # レシピ1本で1バッチ
python tools/step_viewer.py                                # localhost:5000 で目視
python tools/survey_real_parts.py                          # 実車が掃引モデルに収まるか
```

## 構築モデル — なぜ「収まる／収まらない」があるのか

生成器は **1つの断面を、共通の折り軸 w のまわりで掃引する**という構造しか作れない。

* 全ての主曲げの軸が 1 方向 w に平行
* 部品は w に直交する平面内の中心線に沿って断面を掃引したもの
* フランジの根本Rとビードの足Rは**断面の一部**なので、その軸は必ず w に直交する

したがって実車部品がこの枠に収まるかは、**全ての曲げ円筒の軸が w に平行か直交の
どちらかか**で決まる。平板は曲げが無いので自明に収まる（掃引ではなく外形ワイヤで作る）。

## いま量産できる型

全部品が同じゲートを通っている: エッジは直線と円弧だけ（ゲートA、ずれ 0.000000mm）/
外形の境界ループが1本（崩壊検知）/ 隣接面が折り返らない / 締結点が面の上にある /
0.05mm未満のゴミエッジが無い。**穴は開けない**（締結点はアノテーションのみ）。

### 2締結点

| 族 | 特徴 | バッチ | 部品 | 秒/部品 |
|---|---|---|---|---|
| `bead` | 全長を貫くビード（両端は座面手前で平地に戻る） | occt11 | 600 | 0.17 |
| `flange` | 側端フランジ（片側）が折れ目を跨ぐ | occt11 | 600 | 0.17 |
| `rib` | 曲げの内角側の菱形リブ（可変半径のコーナーブレンド） | occt12 | 600 | 0.14 |
| `plain` | 無特徴のパッチ（締結点が近く特徴の余地が無い） | occt12 | 200 | 0.14 |

### 3締結点 — 実車の再現（`docs/PLAN_three_point_2026-09-04.md`）

法線が一致する2点＋別パネルの1点。3点配置を **三角形らしさ = 最小高さ/最長辺**
（0=一直線、0.866=正三角形）で測ると、実車の3型がきれいに分かれる。

| 族 | 実車 | 三角形らしさ（実車 / 合成） | 特徴 | バッチ | 部品 |
|---|---|---|---|---|---|
| `three_point` | 007 | 0.254 / 0.036–0.286 | 片側フランジ、曲げ1本 | occt13 | 600 |
| `three_point_tri` | 011 | 0.765 / 0.60–0.86 | 片側フランジ、対が中心線をまたぐ | occt15 | 600 |
| `three_point_span` | 014 | 0.465 / 0.38–0.59 | **両側フランジ＋中央ビード＋帯幅の絞り** | occt16 | 600 |

`three_point_span` だけが **1部品1特徴の例外**（ビード＋フランジ）。単独点が対から
遠くなる（距離比 011=1.05 → 014=2.04）ぶん曲げをまたぐ荷重が増えるので、実車は
補強を1段足している。

## 今後やるべき型

### 1. 多軸折り — 最大の宿題

注釈のある実車部品（締結点2〜6個）**19件のうち、掃引モデルに収まるのは4件だけ**
だった（007 / 011 / 031 / 1285-20 — 全て上で再現済み）。残る15件は「はぐれ軸」を
持つ、つまり **w に平行でも直交でもない曲げ**がある。

これを作るには断面掃引とは別の幾何エンジンが要る。現状で最も投資対効果が大きい未着手項目。

惜しい候補（はぐれ軸1本だけ）:

| 部品 | 締結 | 面数 | 自由曲面 | 主曲げ | 寸法 |
|---|---|---|---|---|---|
| `A0072600002/026` | bolt4+weld2 | 32 | 3% | 5本 | 108×94×87 |
| `A0072601285/7` | weld2 | 12 | 11% | 2本 | 62×32×14 |

はぐれ軸が小さな遷移面なら、無視して骨格だけ再現できる可能性がある（014 も
はぐれ軸1本で、骨格だけ再現した）。

### 2. 実車に届いていない特徴

| 項目 | 実車 | 合成 |
|---|---|---|
| 両側フランジ | 011 も 014 も両側 | `three_point_span` のみ両側。007型/011型は片側 |
| 帯幅のテーパ | 014 は 50.1→27.4mm | `three_point_span` のみ |
| 曲げ本数 | 014 は2本（39.4°+50.6°） | 3点族は1本固定 |
| フランジ高さ | 007=9.8 / 011=6.9 / 014=4.6–5.8mm | 6–20mm（族による） |
| 011型のΔw | 36.8mm | 到達 30.8–44.5（再現済み） |

### 3. ルールの粒度

* **座面Rが締結種別を区別していない**。実車の溶接は座面クリアランス7.6mmだが、
  我々は一律 12.5〜25mm（ボルト前提）を課している。`three_point_span` だけ
  例外的に溶接相当（7.5〜11mm）を使っている（2026-09-04 ユーザー裁定）。
* **`rib` 族の歩留まりが73.5%**。残りは縫合後に外形が2〜3ループになる型で、未調査。
* **配置クラスの偏り**（occt11 は parallel_same_offset 532 / parallel_opposite 8）。
  レシピの `classes` つまみで補正できるが未実施。
* **アノテーション種別**。生成器は全て `mounting_hole` で書いている（穴は開けないので
  幾何差は無い）。実車は weld / bolt / mounting_hole が混在。

## 設計の申し送り

* **実車が正**。ルールと実測が食い違ったら実車を測って採る。例: フランジの
  「最大折れ角20度以下」は前職由来の申し送りで、OCCT版の実拘束は凹側クリアランス
  `R_bend − h ≥ 2mm` だけだった（実車007/011のフランジは90度の曲げに載っている）。
* **締結点の穴は開けない**。アノテーションのみ。
* **中立面R最小 5mm** と**締結点の必要平面**は既定のルールを踏襲する。
* 族ごとに独立した生成器（`families.FAMILIES`）が「その特徴が成立する配置を狙って」
  引く。何をどれだけどんな多様性で作るかはレシピ（`tools/recipes/*.json`）が持つ。
